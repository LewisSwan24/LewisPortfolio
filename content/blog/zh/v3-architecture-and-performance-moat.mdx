既然这是一份交互与设计工程并重的作品集，阅读体验本身就应该顺滑、克制、经得起检验。在 V3 到 V4 的持续重构里，我保留了读者熟悉的暖纸色调（Warm Paper）与版式呼吸感，真正动刀的是网页背后的数据流：删掉重复维护的元数据，避免首屏加载冗余脚本，并用自动化门禁把无障碍对比度与死链挡在上线之前。

## 把案例正文彻底迁出客户端 i18n JSON

早期版本为了省事，把所有中英文案例全文都塞进了全局翻译文件 `en.json` 和 `zh.json`。由于 `NextIntlClientProvider` 会把消息对象一并注入首屏 HTML，访客哪怕只打开首页，浏览器也要被迫咽下一整套双语长篇文字。

我将全部案例数据统一整理进带静态类型约束与 **Zod** 校验的 `src/data/cases/*.ts` 模块后，客户端包里只剩下导航栏、搜索框与联络页这类轻量的 UI 界面词条，首次渲染立刻轻盈很多；所有图片路径、过程对比卡（`BeforeAfterScrubber`）与 `DesignDecisionTradeoff` 四象限结论也能在构建阶段自动核验。

## 斩断服务端组件渗漏与守住样式体积红线

字典瘦身之后，构建分析仍指向一处异常瓶颈：`/projects` 作品总览页比其他页面沉重得多。排查 `WorkIndex.tsx`，才发现只是为了让顶部筛选标签拥有交互状态，把整块列表都标成 `"use client"`，反而把辅助视图裹进了浏览器脚本。

把静态图文渲染留在服务端页面 `app/[locale]/projects/page.tsx` 并通过 `ReactNode` 插槽传给轻量交互包装器后，列表页脚本体积跌至仅约 **1.25 kB**。<AnchorNote term="服务端插槽边界" label="工程注脚" note="把静态图文渲染留在 Server Component 并作为 ReactNode 插槽传入轻量客户端包装器，可彻底避免展示辅助逻辑打入客户端包。" />

同样，当后续独立上线 [AI 辩护工作台](/zh/ai) 时，所有四象限论证卡与管线自检仪表盘样式全部收口进路由级 `ai-workbench.module.css`，避免污染全局样式表，牢牢守住全局 CSS 不超过 30 kB gz 的构建预算。

| 工程门禁条目 | 缺失时会发生什么隐患 | 自动化校验方式 |
| --- | --- | --- |
| Zod 案例 Schema 注册表 | 中英口径脱节、遗漏诚实局限边界 | `tests/lib/case-registry.test.ts` |
| RSC 服务端/客户端分层 | 无交互案例正文被打入前端 JS | Next.js 路由 Chunk 预算审查 |
| 路由级 CSS Modules 隔离 | 新实验页样式拖慢全站首屏下载 | `pnpm budget:check`（不超过 30 kB gz） |
| 三视口无障碍自动扫描 | 暗黑模式（`#141413`）对比度退化或窄屏溢出 | `e2e/a11y.spec.ts` + Axe 检查 |

## 克制的资源预算、温和动效与互链验证

1. **视觉媒体控量（`pnpm media:check`）**：在不糊掉字号与界面细节的前提下压实截图，并用轻量矢量 SVG 承载流程前后对照图。
2. **克制的转场节奏**：统一收拢至轻量 GSAP 核心与清理机制，尊重 `prefers-reduced-motion` 设置，需要安静画面的访客直接看见终态。
3. **直达可交互现场**：六个核心作品如今全部串连进 [交互实验室](/zh/lab) 与零幻觉 [AI 辩护工作台](/zh/ai)，方便审阅者一边查验代码边界，一边亲手运行真实交互规则。
