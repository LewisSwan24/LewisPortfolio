我在英国斯旺西大学读了四年计算机科学本科（2020–2024，二等一荣誉学位 2:1）。这段训练留给我的本能，是在打磨界面之前先追问：异常输入、并发冲突、断网或掉电时，哪里会坏。毕业阶段写的长篇荣誉论文又加了一条习惯：一个论点能走多远，取决于证据能撑到哪里。

转到昆士兰大学读交互设计硕士（2025–2026）之后，一开始很不适应，好像从确定性一下子掉进了乱糟糟的访谈。等课程项目把软件规则搬到真实的木桌、手腕和嘈杂的房间里，两条训练才接到一起。

## 桌面抽象在现场漏掉了什么

桌面上的状态机默认一个人坐着、盯着显示器。可一旦把四个陌生人拉到 [MazeRunners](/zh/projects/maze) 的亚克力迷宫前，或者把 Claude Code 的遥控搬到 [Walkie](/zh/projects/walkie) 这块手表上，就有三件事变了：

1. **注意力跟着身体走。** MazeRunners 展出时共 9 组 36 人，大约 3 组通关。我们的记录里，玩家盯着球，找同色的队友。陷阱触发靠指套震动告诉他们，有玩家第一次被震动吓了一下。
2. **固件里的时间常数就是交互规则。** FC-51 红外读数会随距离、角度和灯光大幅波动。加了三次取样去抖和 400 ms 冷却之后，球经过一次只记一次，陷阱才显得公平，不像随机乱扣。
3. **高风险操作前要留一点摩擦。** [Lamplight Nook](/zh/projects/lamplight) 遇到高风险卡片时，默认焦点落在「先不要」上。[Walkie](/zh/projects/walkie) 把批准放在正面键，把拒绝放在侧键。[Resume Autofill](/zh/projects/autofill) 只按「下一步」，从不按「提交」。三者都是把状态机里的安全规则写进日常动作。

## 我现在怎么做

2025 年在 UQ 的课程让我在动手做组件之前，先换一种方式框定问题。比如团队项目里的出声思考测试和纸面重画。这些习惯延续到了本站的个人项目里：

- **和 AI 编码工具分工清楚。** Walkie、On The Beat、Lamplight Nook 和 Resume Autofill 的代码大部分由 Claude Code 写成，草原铁潮则是 AI 工具辅助了代码、文案和原创素材。规则由我来定，输出由我审查和验证。状态迁移和拒绝边界先写下来，再让工具生成代码，生成的代码也不会看一眼就当真。
- **写清哪项检查在哪里跑过。** Walkie 的 gate H（屏幕与按键）在真表上通过，gate L 是用一台替身设备经中继跑的。手表离开数据线也能用的那几项检查，目前还没有运行记录，而且只有我自己用过。
- **双语对齐，不藏边界。** 每个案例都写中英两版，两版里的数字保持一致。
