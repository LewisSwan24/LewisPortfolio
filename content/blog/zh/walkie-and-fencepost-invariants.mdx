靠提示词要求模型谨慎，或者在界面上多弹一个确认框，在高频或离桌场景下都很容易被习惯性点掉。在近期做的两个项目里——跑在 M5StickS3 手表上的 [Walkie](/projects/walkie)，以及社区野生动物故事板 [Fencepost](/projects/fencepost)——我尝试把关键信任边界从界面文案下沉为**硬件物理动作**与**数据查询不变量**。

## Walkie：实体按键守住高风险工具审批

离开电脑屏幕用语音指挥编码 Agent 时，最怕的不是识别慢一秒，而是环境噪音误触发或识别偏差直接同意了危险命令。

因此，Walkie 在交互与协议层立了四条硬界线：

- **配对必须物理确认**：只有 30 秒内在手表按下前键，桌面端与手表的 `pair.key` 才允许落盘。
- **权限审批落到实体按键**：Claude Code 发起工具调用时，Node 24 桥接会把请求推入腕上等待队列——前键同意、侧键拒绝（拒绝后可补一句口述理由），语音不再能单独越过权限门控。
- **双启动防误刷保护**：同一支表里还装有 [On The Beat](/projects/onthebeat)，`firmware/guard.py` 直接拒绝 `-t erase` 与 `-t uploadfs`，避免烧录一个应用时抹掉另一个分区。
- **零知识中继传输**：离缆走 Fly.io 中继时全部帧由 AES-256-GCM 封装，中继仅转发密文无法读出正文，而插线时 USB 通道永久优先。

这整套流程在接入真实模型密钥前，先通过了 `gate-h`（11 个真机屏幕按键场景）、`gate-p5`（芯片加解密与 ADPCM 验证）和 `gate-l`（75 秒保活与断线重连）三组门禁校验。

## Fencepost：吊销分享权限的同时切断模型上下文

社区居民分享后院出现的负鼠与鸟类照片时，经常夹杂住处角落、夜间行踪和跨角色讨论。如果只在前端隐藏列表，却没在后端检索路径掐断上下文，AI 助手依然可能「说漏嘴」。

Fencepost 在数据层强制落实两条规矩：

1. **入库即剥离 EXIF**：表结构不保存地理定位等敏感元数据，只保留存储键值。
2. **`access_grants` 直达模型边界**：每条检索链路必须先校验有效授权再拼装模型上下文；一旦居民吊销某个二维码分享链接，后续模型问答就再也读不到对应记录。项目内的 **431 项离线测试** 与 **29 条 AI 安全红线用例**专门验证了这一行为。

公开部署的演示版本为方便课程评审开启了轻量化代号登录，但读取可见性与权限截断不变量依然保持原样生效。

## 共性复盘

无论是手腕上的物理按键开关，还是拼装 Prompt 前的 SQL 权限联表检查，把「绝不允许越界」的不变量放到结构上绕不过去的位置，上层界面才不需要靠繁琐的免责弹窗来弥补焦虑。
