Some reviewers may read a candidate's portfolio through an MCP client inside their editor. I have no data on how many do; this endpoint is a bet that a few will. If that traffic is treated like casual HTML scraping, unlisted coursework can surface in generic queries, and pasted job descriptions can echo secrets back in plain text.

## Enforcing contract boundaries on the server

In this site, `/api/mcp` ships read-only Zod `.strict()` handlers alongside `/.well-known/mcp.json` and `/llms-full.txt`:

1. **Five scoped tools, zero writes**: queries run against listed case studies, pattern specs, protocol replay frames and archive lessons, with no database side effects.
2. **Unlisted work kept out of general answers**: search and tradeoff tools filter to `LISTED_PROJECT_SLUGS`; archived studies are reachable only through the separate `audit_vault_lineage` tool. This is scoping, not access control: the archive itself is not secret.
3. **Secret scrubbing before scoring**: input sanitizers strip emails, phone tokens, `Bearer`, `sk-`, `ghp_` and `AIza` keys before local ranking inside [AI Lab](/ai).
