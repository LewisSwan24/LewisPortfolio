Open a visual canvas too early and every screen looks negotiable. When a model can generate ten sleek dark-mode cards in under a minute, it becomes easy to ship a persuasive flow whose core trust boundary never held.

## What an interaction invariant should specify

This is the checklist I now recommend, not a record of how my earlier projects were run. Before any screen is drawn, three assertions should be written down that neither layout polish nor an AI code pass may break:

1. **Authority boundary**: which actions may run silently (read-only search, local form scanning) and which wait for an explicit human action (a physical front-key press, a manual Submit click)?
2. **Silence over noise**: when the system is unsure, does it fill a plausible guess, or stop in a visible review or blank state?
3. **Recovery chain**: after a cable is pulled, a checkpoint is lost or a grant is denied, what returns the person to a clean state?

Each of my personal builds has answers to these somewhere in its spec or code: [Walkie](/projects/walkie) holds every tool permission prompt until a key is pressed, [Resume Autofill](/projects/autofill) never presses Submit, and [Grassland Iron Tide](/projects/grassland) keeps pause, failure reasons and checkpoints on one save chain. Claude Code wrote most of the code for Walkie and Resume Autofill, and AI tools helped with Grassland Iron Tide's code, copy and assets. For all three I set the rules, reviewed the output and verified it.
