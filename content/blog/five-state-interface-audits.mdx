Most interface reviews spend ninety percent of their time admiring the **Normal** state — when APIs reply in under 200 ms, hardware cables sit firmly plugged in, and every user input matches the schema. Yet real-world trust collapses exclusively in the remaining four states: **Empty**, **Offline**, **Error**, and **Refused**.

Across the six public case studies in this portfolio — and codified inside each case's [Five-State Specification](/projects/walkie#state-matrix) and our [Interaction Pattern Atlas](/patterns) — auditing those five states upfront turned vague UX ideals into falsifiable engineering rules.

## Splitting "Offline" when hardware and cloud relays collide

In [Walkie](/projects/walkie), a generic *"Disconnected"* banner on a 1.14-inch wrist screen leaves the developer guessing blindly while standing across the room from their workstation: did home Wi-Fi drop, did the Fly.io `wss://` relay stall, or did the Node 24 desktop bridge go to sleep?

By refusing a single catch-all offline screen and splitting diagnostics into three explicit states (`No Wi-Fi`, `Relay Unreachable`, and `PC Bridge Offline`), recovery becomes immediately actionable. Plugging in USB-C always preempts wireless frames cleanly, while mid-turn cable changes intentionally drop the in-flight turn rather than risking duplicate tool invocations.

## Designing the Refused state as a first-class feature

In AI-assisted tools, **Refused** is not an error — it is an intentional protection boundary:

| State | Conventional Shortcut | Explicit Trust Boundary |
| --- | --- | --- |
| **Empty** (`Walkie` / `Autofill`) | Auto-pair silently or fill placeholder hints | Require 30s Front Key seal; offer isolated sample dry-run |
| **Offline** (`MazeRunners`) | Throw Web Serial exception on portfolio browsers | Route cleanly to parity-tested Demo Mode |
| **Error** (`Lamplight Nook`) | Retry tool calls silently until budget burns out | Hard spending cap halt card with file copies intact |
| **Refused** (`Autofill`) | Guess visa / essay answers to look 100% smart | Leave double-bordered blank + keep Submit human-locked |

## Auditable constraints over polished illusions

In [On The Beat](/projects/onthebeat), early AI-generated mockups passed visual inspection while hardcoding `MEET` state as static JSON and showing `"1 of 4"` on every prompt card. Checking the **Refused** and **Offline** rows immediately exposed that no real mutual-consent state existed — pushing the build onto an always-on Sydney Fly.io relay where neither phone nor wristband depends on a nearby laptop.
