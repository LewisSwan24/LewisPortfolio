Most interface reviews spend most of their time on the **Normal** state, when APIs answer quickly, cables stay plugged in and every input matches the schema. My view is that trust is decided in the other four: **Empty**, **Offline**, **Error** and **Refused**.

Each public case on this site now carries a [Five-State Specification](/projects/walkie#state-matrix), and the [Interaction Pattern Atlas](/patterns) collects the shared rules. These tables were added to the site in November 2026, after the projects were built, so they document decisions rather than having driven them. Writing them out still shows where a state was left vague.

Walkie, Lamplight Nook, Resume Autofill and On The Beat are personal projects whose code was mostly written by AI coding tools (Claude Code). I set the rules, reviewed the output and verified it.

## Splitting "Offline" when hardware and a cloud relay meet

On [Walkie](/projects/walkie), a generic *"Disconnected"* banner on a 240×135 wrist screen would leave the wearer guessing: did the Wi-Fi drop, did the Fly.io relay stall, or did the PC bridge go offline?

So the offline screen names which link is down (no Wi-Fi, no relay, or PC offline) and says when plugging in USB will help. Plugging in the USB cable always takes over from the wireless link, and a cable change in the middle of a turn drops that turn rather than risking a duplicate tool call. The wireless path itself has not yet been run on the watch away from the cable.

## Designing the Refused state as a first-class feature

In AI-assisted tools, **Refused** is not an error. It is a protection boundary:

| State | Conventional shortcut | Explicit boundary |
| --- | --- | --- |
| **Empty** (`Walkie`) | Pair silently | A new pairing key is adopted only after a front-key press within 30 seconds |
| **Offline** (`Walkie`) | One "Disconnected" banner | Names the link that is down; USB takes over when plugged in |
| **Error** (`Lamplight Nook`) | Retry tool calls until the budget is gone | Each run has a spending cap and stops when it is reached |
| **Refused** (`Autofill`) | Guess visa or essay answers to look complete | Leave the field with a 3px outline for the person, and never press Submit |

## Checkable constraints over polished illusions

On [On The Beat](/projects/onthebeat), the early AI-built version looked finished, but its `MEET` screen showed mocked data. On 25 September 2026 I pointed out that nothing would run without a laptop. Sixty-five minutes later, two wristbands showed `MEET` together through a relay on Fly.io. I caught that myself; it did not come from a five-state review, and the table came later.
