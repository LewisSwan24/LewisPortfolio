Accessibility work has a default checklist: check the contrast, size touch targets generously, write alt text, never encode meaning in colour alone. That list is genuine and I use it. Building Spectra Lens, an archived browser extension experiment that adds reading aids to any site, showed me that the checklist covers the part someone else has already settled.

The hard part has no guideline. You are a guest on someone else's page.

## What the extension actually does

The popup offers a set of separate aids rather than a general CSS editor: colour-vision filters, an "OpenDyslexic + spacing" switch, a reading ruler with adjustable height, colour and opacity, high contrast, a font-size scale, link highlighting, a large cursor and reduced motion.

The dyslexia switch is a single toggle with fixed values. When it is on, the page's text uses OpenDyslexic with a line height of 1.5 and letter spacing of 0.05em. There are no separate sliders for line height, letter, word or paragraph spacing. WCAG's text-spacing criterion names those four properties with thresholds a page should survive; the extension does not expose them one by one, and its letter spacing sits below the WCAG figure.

## What the guidelines do not settle

**Injected styles compete with the page.** A stylesheet added by an extension has to beat the page's own rules. Spectra Lens marks its rules `!important`, which wins over ordinary page styles, though a page's own `!important` rules can still interfere. I did not keep notes on which sites resisted.

**Single-page apps are untested.** The repo has no code that watches for route changes, and I did not test single-page apps, so whether the settings survive their navigation is unknown.

**Settings are global.** They are stored once in `chrome.storage.local` and apply on every site. Saving settings separately for each site is a possible next step, since loose spacing may suit a dense documentation page more than a long article. The extension does not do this.

## The font

At runtime the extension loads OpenDyslexic from a file in its own folder, not from a CDN; a setup script downloads that file once at install. One argument for this is privacy: a runtime request to a font host tells the host which pages are being read. I did not record whether that was my reason at the time, so treat it as an argument, not a decision log.

## The honest boundary

Nobody who needs this has used it. I did no user research for it.

Every control is reasoned from general guidance, not from watching a reader. That is enough to build something and nowhere near enough to claim it helps. The next step is the one I have not taken: give it to someone who reads this way and watch which aids they never touch.

It is a demo. It runs, the settings layer has unit tests, and it has never faced a store review.

## What I took from it

Compliance rules are a floor, and a floor worth having: they encode failures the field has already paid for. But they describe an *interface you control*. Once your work has to live on someone else's page, much of the difficulty sits where the checklist never looks.
