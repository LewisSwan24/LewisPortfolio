Prompts can ask a model to stay cautious, and confirmation dialogs can ask a user to double-check. Neither holds up well under fatigue or asynchronous workflows. Across two recent builds—[Walkie](/projects/walkie) on an M5StickS3 watch and **Fencepost** as a community wildlife storyboarding app—I pushed critical safety boundaries down out of UI copy and into hardware inputs or query invariants.

## Walkie: physical keys as the permission boundary

When directing Claude Code across long tasks away from a desk, voice interaction is tempting right up until the agent asks to run a destructive shell command or write outside its workspace. Approving that solely by voice fails easily in a noisy room or via mis-transcription.

Walkie solves that by making the **physical button layer** on the M5StickS3 non-negotiable:

- **Explicit pairing**: Saving a desktop pairing key requires pressing the front button on the watch within a 30-second window.
- **Discrete approval queue**: Tool permission prompts pause the Node 24 bridge until the front key (approve) or side key (deny, with optional spoken reason) is physically pressed.
- **Dual-boot safety guard**: Because Walkie shares the watch with [On The Beat](/projects/onthebeat), `firmware/guard.py` blocks full flash erase commands so updating one app cannot wipe the sibling partition.
- **Zero-knowledge relay**: Beyond the USB cable, frames use AES-256-GCM under a session key derived from `pair.key`, so the Fly.io relay never sees plaintext prompts or tool names.

All three hardware verification scripts confirm pairing cryptography, on-device pagination, and relay keep-alive behavior on real M5StickS3 hardware before connecting any live model key.

## Fencepost: revoking access cuts the model off too

In neighborhood wildlife storyboarding, sharing backyard sightings involves private home context, family reading, and neighbor moderation. UI visibility toggles alone feel fragile if text from a revoked link lingers inside an AI assistant's retrieval context.

In Fencepost, two rules live in the data boundary itself:

1. **No EXIF storage**: Media uploads strip location metadata on ingest so home coordinates never enter the database.
2. **Query-level `access_grants` enforcement**: Every retrieval query joins active sharing grants before assembling model context, verified through automated privacy checks and red-line prompt reviews. When a resident revokes a QR grant, subsequent assistant answers immediately stop referencing the hidden sighting. <AnchorNote term="query-layer invariant" label="Architecture note" note="Separating timeline queries from assistant context queries means UI caching never leaks revoked data back into an LLM prompt." />

The live public build on Vercel intentionally leaves demo handle login lightweight so reviewers can inspect flows directly, while keeping grant enforcement intact at the data layer.

| Trust Failure Surface | Soft UI Warning (Brittle) | Structural Hard Invariant (Walkie / Fencepost) |
| --- | --- | --- |
| Destructive shell prompt | Voice confirmation (`"Yes"`) or modal dialog | Physical S3 Front/Side button pause inside Node 24 bridge |
| Shared firmware flashing | Warning banner in README before running esptool | `firmware/guard.py` aborts `-t erase` and `-t uploadfs` |
| Cloud relay privacy | TLS transport while relay parses plaintext JSON | End-to-end AES-256-GCM envelope keyed to `pair.key` |
| Revoked AI retrieval access | Hiding item in React UI while prompt context stays stale | SQL `access_grants` join enforced directly before prompt assembly |

## Shared lesson & next inspection

Good interaction design for autonomous tools does not stop at polite microcopy. Whether the boundary is a tactile watch switch over AES-256-GCM or a SQL join gate before prompt construction, placing the safety invariant where bypassing it is structurally impossible makes every higher-level interface calmer to use.
