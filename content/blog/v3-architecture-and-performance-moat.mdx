A portfolio built for design-engineering roles should stand up to the same inspection a production product team runs on its own frontend. During the V3 refactor of this site, I audited every byte shipped to the browser and every place where case-study facts were duplicated across files.

The goal was not a visual rewrite—the warm-paper Lively Icons design system already fit the work. The goal was removing hidden coupling and making every quality claim enforceable in CI.

## Moving case studies out of client JSON bundles

Earlier versions stored narrative case-study copy inside global i18n JSON bundles (`en.json` and `zh.json`). Because `NextIntlClientProvider` serialized the entire dictionary into HTML, every visitor downloaded bilingual essays for ten projects just to render the navigation bar.

Moving all fourteen project records (ten listed cases and four unlisted archives) into typed `src/data/cases/*.ts` modules validated by **Zod 4** reversed that cost immediately:

- `en.json` dropped from roughly **99 KB to 16 KB** (-83.5%)
- `zh.json` dropped from roughly **52 KB to 11 KB** (-78.7%)
- `NextIntlClientProvider` now forwards only client-required UI namespaces (`brand`, `nav`, `footer`, `contact`, `resume`, `search`, and layout chrome)

Every case slug, image asset path, work summary row, and proof review window is checked statically on push by `pnpm proof:validate` and Vitest.

## Stopping client boundary creep on the Work Index

Even after shrinking global dictionaries, one route stood out in Next.js 15 build output: `/projects` carried **80.2 kB** of route JavaScript (**204 kB** First Load JS), almost entirely inside a single `WorkIndex` client wrapper.

Tracing its imports explained why: the interactive category tabs pulled in four SVG schematic components, hiring shortlist summaries, the capability evidence matrix, and proof helpers—all inside `"use client"`. Moving those blocks up into the Server Component (`app/[locale]/projects/page.tsx`) and passing pre-rendered thumbnail slots left only the lightweight tab-filter wrapper on the client. After rebuilding, the `/projects` page chunk fell from **80.2 kB to 1.25 kB** (`First Load JS: 125 kB`), allowing the CI bundle gate (`pnpm budget:check`) to lock per-route app chunks strictly under **20 kB gzipped**.

## Replacing heavy assets and ad-hoc motion

Three smaller shifts closed the rest of the loop:

1. **Media pipeline (`pnpm media:check`)**: Using `sharp` and `ffmpeg` compression brought project media down from `18.15 MB` to under `8 MB` across all cases while keeping a hard `12 MB` CI ceiling.
2. **Unified GSAP core**: Removing `framer-motion` in favor of centralized `gsap.context()` cleanup and lazy `ScrollTrigger` reduced the home route First Load JS from `175 kB` to `158 kB` while honoring `prefers-reduced-motion`.
3. **Automated accessibility checks**: `@axe-core/playwright` now scans Desktop Light, Desktop Dark (`#141413`), and Mobile (`375px`) viewports in CI, alongside `a[href='/resume.pdf']` omission checks that keep the web resume and print stylesheet as a single source of truth.
